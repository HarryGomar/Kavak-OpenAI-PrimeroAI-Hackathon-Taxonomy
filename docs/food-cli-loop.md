# Integrated Food improvement through the installed CLI

The owner-selected Pedia-inspired baseline is the reference. The full Food adapter
executes fresh blind validation, gold-backed feedback comparison, the existing proposer
and improver factories, feedback analysis, controlled placement and checklist trials,
canonical gate diagnostics on development comparisons, and native distillation records.
Every model role uses the pinned Codex command-line interface (CLI) transport.
The earlier `continue_loop` command is a preliminary card trial, not the full harness.

Use the single `executable_loop` entry point below for integrated rounds. It loads
immutable `system-state` versions containing extraction/lattice/vocabulary, executable
configuration and routing, placer card/tools, validator setup/tools, and the actual
retained full-pipeline output. Current CLI concurrency is capped at **20** in the shared
transport. It executes fresh independent validation, the broad proposer and improver,
component comparisons, and the integrated candidate before retaining a version.

Changed placer instructions and executable routing receive actual placer calls on
their routed observations. Free deterministic paths pass the same source grounding.
Code/config-only, placer-only and combined arms are compared when applicable; identical
arms share the same actual measurement. Cached agent-fallback replay is confined to
`executable_changes.evaluate` isolation diagnostics and is never the final integrated
measurement. Unsupported checks remain implementation proposals until code, declared
positive/negative cases and actual evaluation exist. Candidate Python tools are tested
in an isolated worker and made available only to the candidate arm.

Placer proposals can append a general instruction or replace the complete instruction;
both execute the actual placer and preserve source profiles and qualified tools. The
optional `--original-source-cohorts-candidate` trains the executable lattice on the
hash-verified original source corpus, without gold-derived brand registries, while
scoring only the unchanged frozen sample. Broader training does not increase the
scored denominator. Source-only brand corroboration supplies unverified original
reported claims and never assigns an identity automatically.
`--identifier-peer-evidence-candidate` adds bounded original-source peer quotes only
after checksum, source-grain, organization, title-overlap and ambiguity checks. Generic
barcodes and differing package quantities remain explicit limitations. Peer provenance
cannot name nodes, and peer-only words cannot name the target variant. This optional
context requires its own measured comparison; qualification alone is not improvement.

An optional image candidate uses `image_evidence` to download a bounded set of original
URLs whose provenance identifies the exact selected variant. It preserves current
retrieval time, original bytes and hashes, then executes literal transcription with
the pinned CLI's image attachment support. Download failures and uncertain text remain
explicit; only qualified text is supplied to the candidate placer. The sidecar binds
the source, helper, actual prompt/schema/pin, attachment and completed-call artifacts.
It does not establish what image bytes existed on the original collection date.
Image-only variant naming remains refused. The final pipeline still needs paired
evaluation; attachment support or successful transcription is not an accuracy gain.
Prepare with `python -m domains.food.image_evidence --root <frozen-root> --name
source-image-ocr-018 --intended-loop loop-018`, then pass the resulting immutable
sidecar to `executable_loop --selected-image-text-candidate <sidecar>`. Preparation
calls count once in that intended loop; subsequent retained reuse counts zero fresh
reader calls. Run preparation before the integrated runner: the shared 20-call
semaphore applies within a process, not across independent Python processes.

`image_text_spans` tests a different source extraction contract on preserved images
whose earlier transcription was uncertain. It requests literal spans with separate
uncertainty flags, drops uncertain spans, and preserves the retained reader's already
qualified text. The original extractor stays pinned. Its new sidecar binds the old
sidecar and the new actual calls; the placer accepts only these two explicit formats.
Use `python -m domains.food.image_text_spans --root <frozen-root> --name
source-image-spans-020 --intended-loop loop-020 --base-sidecar <retained-ocr-sidecar>`,
then evaluate the new sidecar through the same integrated entry point. This reader
uses at most 18 CLI slots, allowing only the two feedback calls to overlap while the
combined maximum stays 20. Evidence coverage is reported separately from gold gains.

For no-tool, single-row placer calls, an unchanged CLI request may reuse its prior raw
structured answer only after exact prompt/schema/pin/executable and completion checks.
Receipts identify the prior inference; the current grounding, rules and scorer run
again. Changed or unverifiable requests execute normally. These reused observations
are counted separately from fresh calls and are not independent replicates. Blind
validators still execute anew each cycle. This is distinct from diagnostic fallback
placement replay, which remains excluded from final integrated evaluation.

The continuation retains a candidate for development only if exact identity matches
increase without aggregate brand or strict full-path matches decreasing. Paired gains
and regressions remain visible. An incomplete batch run cannot win. This selection
does not admit learned production rules: the existing 50 observations have already
been inspected, and Food has no sealed-gold gate here. Model variability also affects
differences. No scope accuracy, served tier, dollar cost, or population claim is inferred.

Remain at 50 observations until about 45/50 exact identity matches and regression
checks support expansion; then evaluate 500 and 5,000 source observations. A completed
run alone does not authorize advancement. The canonical gate's exact, touched-row,
and Wilson-bound checks are reported on development evidence separately from the
unavailable untouched Food sealed gate. Production admission stays blocked. At each
stage, report actual source and scorable gold counts and previously inspected overlap.
The subset has 5,000 source rows and 4,500 sidecar labels; stricter verified joins
currently leave 3,886 eligible rows. These are different denominators.

The current validator is called anew in every cycle. An accepted checklist proposal
gets another actual blind call per batch; an unsupported proposal is explicitly rejected.
The existing proposer/improver receive only the authorized feedback partition.
Rule proposals with unsupported check parameters are refused before execution.
The unchanged canonical `taxo.gate.decide` runs as a development diagnostic; it does
not make a sealed read. `taxo.distill.record` and `taxo.distill.lessons` record and
process pending rounds without activating lessons. `curator.admit` applies only to
qualified deterministic checks, and is explicitly skipped for instruction, extraction,
vocabulary and question proposals. A check without actual fire/quiet qualification
and gold shadow counts cannot be admitted. Diagnosis runs within the broad proposer;
there is no separate analyst call in this entry point. Older rounds without these
postmeasurement stages remain identified by their original artifacts.
For an explicitly qualified registered-check experiment, `curate_rule_trial` replays
saved positive/negative qualification, verifies the implementation hash, derives
feedback-only shadow counts, and calls the unchanged native curator in a separate
diagnostic memory directory. Repeated curation attempts share the same measurement;
their counts must not be added together. This diagnostic cannot override rejection
of the measured full system or publish an active production rule.
`--resume` preserves completed actual validation calls within the same interrupted
cycle instead of repeating or replacing that stage with historical judgments.

Each run saves incremental batch progress, actual transport attempts, failed rows,
intentional parks, grounding rejection counts, exact rule snapshots and hashes,
placements, proposed nodes, frozen scoring, paired deltas, counterexamples, usage,
and a hashed artifact index. Failed calls are retained without automatic retries.
Source-bearing logs stay outside Git. Native `memory/rounds/food` records contain
aggregate development results; `keep`, `decided_on`, and `gate` remain null.

Scaling freezes a deterministic hash-ranked sample from the **same source subset**,
restricted to verified one-to-one gold/selection joins. It verifies raw, selection,
and sidecar hashes, native identifiers, source titles, mention/entity/brand joins,
and hierarchy consistency. The eligibility exclusions and overlap with the old sample
are recorded. Consequently these are gold-eligible development observations, not a
random sample of all marketplace listings or a brand-sealed holdout. The original
source and gold files remain unchanged. No independent validator judgments are
invented for newly added observations. Their first run has no paired comparator.
