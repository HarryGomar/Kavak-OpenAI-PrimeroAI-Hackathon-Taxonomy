Pedia, our last project · 245 held-out listings · mean of 6 runs

Hill-climbing is hard, and continual learning is not a solved problem. Evals are what drive performance. In our last project a loop improved its own rules and climbed its own eval, an LLM judge, from 78% to 87%. When we checked by hand afterwards, it had gone from 81% to 84%: a third of the gain. 15 of the 48 changes it kept made our labels worse. Where a task checks itself, a loss or a test suite, that's enough: Karpathy's autoresearch hill-climbs on its own. Most useful tasks have no such check. So the eval itself needs a method to improve: what counts as right, and how we check it. That's what this talk is about.

Different shops, different words: one product each. The tree is what we build.

The task comes from our own work. To understand a market you connect its listings into product trees. Every shop writes the same product differently: Amazon says Double Stuf Golden, Walmart says Golden Double Stuf; Walmart repeats the brand, TikTok writes it in capitals. Under the noise, these six listings are three products: Oreo Double Stuf Golden, Lattafa Khamrah, and Khamrah Qahwa. Until you know that, you can't add up a product's price, reviews or demand. It looks trivial for a person and is hard for an agent: a size or a 12-pack is never a new product, but a flanker like Khamrah Qahwa is.

These are the three things we want to improve. Accuracy: an agent on every listing places 85% of fragrance listings exactly right, but it can't check its own work, as we just saw. Rules plus the agent get 75% today, at a ninth of the cost: closing that gap is what loops 1 and 2 are for. Loop 1 learns rules from a few labels, and loop 2 makes the check stricter. On food, a new domain, the agent gets 45% and rules plus the agent 20%: that's where loop 3 has to help. Cost: the agent uses about 630 tokens a listing. For two million listings that's about 1.3 billion tokens, around $3,800 a pass, and we pay it again on every refresh and in every domain. Rules place 89% of fragrance listings for free, so the bill falls to about $400. Speed: at a second a listing, one call at a time, that's about 570 hours. Rules take a millisecond a listing, and loop 3 lets each new domain start from the last one's lessons.

Round 1: the validator matched gold on 75% of 40 fresh listings, and 82% of its flags were real errors. Round 3: 85%, and every flag was real.
Each round it labels 40 more listings. The loop runs until silver matches gold.

This is one domain, fragrance, on its own branch. Listings go through the rules first, for free, and the placer agent gets only the 11% the rules can't place. Loop 1: the proposer agent reads the errors on silver and gold and proposes one rule change, and a gate in code keeps it only if exact match on sealed gold rises. Loop 2: the validator agent checks fresh listings the rules have never seen, and a person labels what it flags. The improver agent makes the validator better from those labels, round after round, until its silver agrees with the person's gold. Those labels grow silver and gold, and the patterns behind them go to loop 1. Loop 3: every domain runs the same loops on its own branch, distil turns kept changes into lessons, and a lesson kept in two domains goes to all of them.

Loop 1 changes three things in the rules.

Memory

what words mean

− elixir, intense]round 2

+ hair, travel, mist]round 1

+1.4points: hair, travel, mist; Elixir, Intense

Operators

the steps, in code, called by rules

# rules/settle-single-name.yaml
+when: name seen once,round 6
+ in 3 listings or fewer
+then: {place: own product}
+found_by: loop 2

+15.1points, with the brand's own store and the shop's URL

Tools

checks that stop a wrong placement

# rules/veto-set-conflict.yaml
+check: set_conflict
+status: activekept
# rules/child-typed-form.yaml
×check: form_conflict
×status: shadowdropped

−501wrong placements, with the set check on (food)

A gate in code keeps a change only if sealed gold clearly improves. Together: 52% → 69% exact.

Loop 1 doesn't touch the agent. It changes three things in the rules, and each is a file you can read. Memory, what words mean: the vocabulary learned that hair, travel and mist are never part of a name, and that Elixir and Intense are not concentrations. A point and a half. Operators, the steps in code that rules call: when a name is seen only once, in three listings or fewer, it is still its own product; that came from loop 2. With the brand's own store and the shop's URL naming the brand, fifteen points. Tools, checks that stop a wrong placement: the set check, a gift set is never one product, works; on food, turning it off adds 501 wrong placements. A form check, a body mist as a typed child, didn't: the gate dropped it, and it only logs now. Together, exact match on sealed gold went from 52% to 69%.

Loop 2, validation: improve the eval itself.

Gold: labelled by a person. Silver: labelled by the validator, every disagreement settled by a person.

Errors it found, like short names seen only once, became a rule, kept in round 6.

Each new eval: loop 1 adds rules and climbs again

The validator: v1 → v2 kept, 82.5% → 85% match with gold. Two later tries matched no better, so they were dropped.

A small gold set doesn't cover everything, so loop 2 improves the eval itself. Going round the loop: a validator agent checks listings nobody labelled. It flags errors, and cases it isn't confident about. A person settles them. Where the solver was wrong, the case joins gold: gold 2. The rest is kept as silver. From that come better rules, and a better validator. So each round there is more silver, and it is built better: the eval covers more and gets stricter. Then it asks what is going on: for example, short product names seen only once; that became a rule, which the gate kept in round 6. That goes back into the rules, and into a stricter check, so confidence goes up. On the graph: each eval gets a full loop 1 climb. Eval 1 is gold alone: loop 1 climbs from 52% to 69%. Loop 2 then builds eval 2: the validator's silver, and the flags a person settled as new gold. On it the solver scores lower, lowest on silver, and loop 1 climbs again. Eval 3 has more of both, labelled by a better validator, version 2, which matched gold 85% of the time against 82.5% for version 1. Each climb adds rules: five on eval 1, eight by eval 2, ten by eval 3. Each time the gap between silver and gold closes, and the loop runs until silver matches gold. We improve two things at once: the eval, and the solver underneath it.

Every domain runs on its own branch, and distil, which is code, turns each change the gate keeps into a lesson with its scope and its record. Loop 3 tries each domain's lessons on every other domain's sealed gold. Food's cleaning lessons carry: dropping sizes, multipacks and shop noise, and reading the brand from the shop's own store, makes fragrance titles clean too. Fragrance's structure lessons don't carry back: a flanker like Khamrah Qahwa is a new product, but a new Oreo flavour is a variant. On fragrance's rules food starts at 11% exact, where the agent alone gets 45%. So a lesson goes global only once two domains have kept it.
