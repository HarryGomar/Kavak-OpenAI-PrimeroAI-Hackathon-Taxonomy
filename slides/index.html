Introducing

is a two-fold system that learns how to build the trees

Fold 1Inside one domain

Induction loopTurns a hand-labelled gold set into cheap rules. Raises F1 on gold, lowers the cost.

Validation loopFinds the errors gold can't show, on fresh listings. Grows the gold and sharpens the validator.

Fold 2Across domains

Meta loopCarries the rules and checks that worked to the next domain, so it starts ahead.

- We introduce Taxo, a two-fold system with generalisable learning for this task. - First, inside one domain, two loops. Induction turns a hand-labelled gold set into rules. Validation goes looking for the errors gold can't show. - Second, across domains, a meta loop carries what worked to the next domain.

- Inside one domain, we start from a gold set that a person labelled by hand. - The induction loop tries to turn it into deterministic rules, so that agents only see the hard cases. Three kinds: - The lattice counts word sequences across all of a brand's listings. "Khamrah" is in five titles and "Khamrah Qahwa" in two, so Khamrah is a family and Khamrah Qahwa is a product. No word lists. - A registry. An agent searches the web for each brand's official lines, and code writes them as a file the rules can read. - A route. What is left goes to the cheapest agent that can settle it: the title alone, the title plus the description, or a web search. - Each round, an agent reads the errors and proposes one change. A gate in code keeps it only if it helps on gold that nobody tuned on. - The goal is two numbers: more of gold labelled right, at a lower cost.

Inside one domain · Validation loop

Gold doesn't cover everything, so a second loop goes looking for errors

Gold is small, and a person chose it. Even with a clean test split, it can't contain every error a rule will make.

An agent labels fresh listings on its own, with more budget than the pipeline. Where it disagrees with the rules, a person settles it.

Each round leaves a frozen validation set, and new errors for the induction loop.

In our earlier system, a rule matched the agent 145 times out of 145 and was marked as holding. Its truth was the agent it was meant to replace.

- But the gold set doesn't cover everything. Even with a clean test split, we can't say the rules generalise: a person chose those cases, and they can't contain every error a rule will make. - That is why we have the validation loop.   size: ['\d+(\.\d+)?\s?(ml|oz|fl oz)']
  concentration: [eau de parfum, edp,
    eau de toilette, edt, parfum, extrait]
  audience: [for women, for men, unisex,
    pour homme, pour femme]
  form: [spray, travel size]

registry/fragrance/lattafa.yaml · built by an agent, written by code
brand: Lattafa
aliases: [lattafa, lattafa perfumes]
nodes:
  - {id: F_khamrah, level: family,
     name: Khamrah}
  - {id: P_khamrah_qahwa, level: product,
     name: Khamrah Qahwa, parent: F_khamrah}
basis:
  P_khamrah_qahwa: {source: official,
    ref: lattafa.com, found_by: agent_search@v1}
The vocabulary says which tokens are variants rather than names; the lattice strips them before counting. The registry holds the official structure: an agent builds it with web search and returns a proposal, and code writes the file and keeps the evidence.
