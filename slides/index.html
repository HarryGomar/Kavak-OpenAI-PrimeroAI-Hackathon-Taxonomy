Taxo

Learning to build product trees for any commerce domain

Kavak × OpenAI × Primero hackathon · 9 November 2026

We're going to show you Taxo: a system that learns how to turn messy marketplace listings into clean product trees, and gets faster at it with every domain it sees.

To improve a system, you need a score it can't move by itself.

Before the problem, the lesson that shaped Taxo. Self-improving systems are easy to build and hard to trust. In Pedia, our last project, a loop changed its own rules and an LLM judge scored each round. The judge went from 78% to 87%. The owner's hand labels went from 81% to 84%. 15 of the 48 changes made the judge happier and the labels worse, and the loop kept every one. Hill-climbing only works if the score can't be moved by the system itself. That is the design constraint for everything that follows. The obvious answer is to send every listing to an agent. At [$c] per thousand listings, four million cost [$C] for one pass, and again for every refresh and every new domain. And it is wrong in ways you can't see: on gold the agent alone scores [f]; in Pedia, 59% of the food listings the agent set aside as unplaceable were real products. So this is not over-engineering a labeller. Rules are free, readable and testable; the agent gets only what they can't settle.

Taxo: a pipeline of free rules, and three loops that improve it.

This is the system. In the middle, the pipeline: listings go through free rules (parse, brand, registry, lattice), and only what they can't settle goes to an agent, paid per call. Above it, the induction loop: run on the hand-labelled gold set, an agent reads the errors and proposes one rule, and a gate in code keeps it only if F1 on sealed gold rises. Below it, the validation loop: a validator agent labels fresh listings blind; where it disagrees with the pipeline a person settles it, and that becomes new gold. On the right, the meta loop: what worked, with its scope, starts the next domain.

Taxo is two-fold: loops inside one domain, and a loop across domains.

Taxo is two-fold. Inside one domain (zoomed in on the right): induction turns gold into rules, the pipeline runs them with an agent for what's left, and validation finds the errors gold can't show, settled by a person. Across domains (on the left): the meta loop carries the lessons from food to fragrance to cars.

Code does the work, agents do the judgment, a person decides what's true.

Read it by column. Placing listings: code settles most of them, the cheapest agent gets the rest. Induction: a person labels gold, an agent proposes rules, code gates them on sealed gold. Validation: an agent labels fresh listings blind, a person settles every disagreement and teaches the validator. Meta: code keeps what worked, with its scope, and the next domain starts from it. No step lets a system grade itself.

Inside one domain we start from a gold set a person labelled by hand. Each round: run the rules on gold, an agent reads the errors and proposes one change, a gate in code tests it on sealed gold nobody tuned on, and it is kept only if F1 rises and cost doesn't. What it keeps is a file you can read, like this registry for Lattafa, and the lattice counts that turn titles into families and products.

But gold doesn't cover everything. Even with a clean test split we can't say the rules generalise: a person chose those cases. So the validation loop: an agent labels fresh listings on its own, with more budget than the pipeline, and brings up the errors the system is making. Where it disagrees, a person settles it. Each round gives a new frozen validation set. Rule set 1 scores [x] on gold, [y] on validation set 1 and [z] on validation set 2: fresh listings find errors gold never showed us.

The method

  • Turn agent judgment into rules you can read, test and run for free.
  • Never let a system grade itself: agents hunt errors, a person decides.
  • Keep what worked, with its scope, so the next problem starts ahead.

The tree is the first task. Next:

  • Matching the same product across shops
  • Cars at Kavak: make, model, version and trim decide the price
  • Demand and trends, once search terms roll up to a product
  • Any agent work that has to be trusted at scale
This is not a labelling system. The tree is the first task; the method is the point: turn agent judgment into rules you can read, test and run for free; never let a system grade itself, so agents hunt for errors and a person decides what is true; keep what worked, with its scope, so the next problem starts ahead. It goes to matching across shops, cars at Kavak, demand and trends, and any agent work that has to be trusted at scale. Systems will always say they're right. Taxo doesn't take their word for it.
